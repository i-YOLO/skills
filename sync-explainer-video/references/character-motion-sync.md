# 逐帧人物动作同步契约

本文件只定义如何调用与同步已有动作。新建、拆帧、注册、验收和晋升资产时读取 `$madem/references/character-motion-production.md`。

## 资产解析

1. 读取 `$madem/assets/registry.json`。
2. 用 pack ID 找到角色动作资产包，再读取 pack catalog。
3. 用 `motion_asset_id + facing + motion_variant` 唯一解析动作序列。
4. 检查状态、源帧率、阶段节点、逐帧 tick、落定帧、占位框、道具轨迹和文件哈希。
5. 默认只使用 `project-proven` 或 `library-approved`。使用 `candidate` 时必须在项目记录中写明显式采用，并保留技术和人工视觉报告。
6. 把组件和实际使用的帧、道具与 catalog 快照复制到视频项目；同步和渲染都读取项目内副本。沿用项目既有资产目录，并把来源与哈希写回现有 `video-job.json`、`timeline.json` 或 `qa-report.json`；不要仅为角色动作发明新的全局目录或 manifest schema。

无法唯一解析、文件哈希不匹配、所需朝向/结果分支缺失或资产状态不允许时，停止同步该动作。不要临时镜像、替换结果分支或从知识库路径直接引用文件。

## 阶段绑定

使用 pack catalog 的阶段节点，不按总帧数平均切分：

- `idle`：角色提前静止出现；`sync_required: false`。
- `prepare`：视线、蓄力或接近动作；绑定准备词或前置动词。
- `key-action`：指向、接住、核验、阻挡等核心动作；绑定真实关键词。
- `outcome`：成功、失败、找到、未找到等结果；绑定结果词。
- `settled`：结果落定；从 catalog 落定帧开始，至少保持 `1.0s`。

同一动作的阶段使用相同 `sequence_group_id` 和递增 `sequence_index`。每个需要同步的阶段都建立独立 `sync_events`；不得只同步整段动画的开始时间。

## 节奏调整

- 保持 catalog 的逻辑帧顺序、源 fps 和阶段内部 tick 比例。
- 输出 60fps 时按源 tick 重复显示；不得把重复显示称为新补间帧。
- 场景时长差在 `±20%` 内，可调整准备前等待、阶段间短停和落定保持，但不能跳过关键帧。
- 不要通过光流补帧、CSS 镜像、局部慢放、任意丢帧或压缩回弹阶段来硬贴词位。
- 动作太长时，优先更换较短资产或让 `$madem` 制作短版；动作太短时，优先延长落定帧或增加有语义的后续画面。
- 关键词落在两个动作阶段之间时，以调整阶段起点为先；不要移动真实词时间。

## 占位与退场

- 使用 catalog 推荐显示高度，默认 `320px`、建议 `280–340px`、硬上限 `380px`。
- `occupied_rect_1080p` 必须完全位于预留角色槽位，底部不得超过 `y=820`，不得覆盖字幕安全区、标题、卡片或连线。
- 每幕最多一个角色动作。
- `visual_exit_start - settled_at >= min_settled_seconds`，其中结果与落定默认至少 `1.0s`。
- 退场发生在落定保持之后；不得在回弹或结果尚未读清时切走。

## 审计证据

项目至少保留：

- pack ID、pack catalog schema 版本和状态。
- `motion_asset_id`、朝向、结果分支和阶段节点。
- 项目内 catalog/资产路径与哈希校验结果。
- 每个阶段的真实词位、视觉时间、误差帧数和落定保持。
- 角色槽位与 `occupied_rect_1080p`。
- 正常显示尺寸的事件帧和最终编码 MP4 视觉复核。

同步检查通过不代表动画本身自然。若事件帧或播放中出现身体漂移、比例跳变、阶段交接顿挫、道具脱离或五官闪烁，把问题交回 `$madem` 修复资产，不要在时间轴层隐藏。
